# 🛠️ Troubleshooting: 따릉이 VOC 분석 파이프라인 개발 및 튜닝 기록

본 문서는 서울자전거 따릉이 앱 사용자 VOC 분석 리포트 프로젝트 중 발생한 데이터 수집, 형태소 전처리, 단어 네트워크 분석, 그리고 비지도 토픽 모델링 단계의 기술적 장애와 해결 과정을 상세히 기록합니다.

---

## 📌 Case 1. 애플 앱스토어 수집기 작동 실패 및 KeyError
### 1. 현상 (Symptom)
*   `crawl_appstore_large` 함수 실행 중 `latin-1` 인코딩 코덱 에러 발생.
*   에러 발생 후 빈 데이터프레임이 생성되면서 존재하지 않는 컬럼(`userName`, `rating` 등)을 인덱싱하려다 `KeyError: "None of [Index([...])] are in the [columns]"`를 던지며 프로세스 강제 종료.

### 2. 원인 분석 (Root Cause)
*   **잘못된 App ID 지정**: 기존 소스에 기입된 앱 ID(`1196024823`)는 따릉이의 ID가 아닌 다른 앱의 정보였으며, 실제 따릉이 App Store ID는 **`1041695427`**임이 밝혀짐 (404 에러 발생 원인).
*   **URL 한글 인코딩 충돌**: `app-store-scraper` 라이브러리가 내부적으로 `requests.get`을 수행할 때 URL에 한글(`서울자전거-따릉이`)이 섞여 리다이렉트되면서 `requests` 라이브러리의 유니코드 경로 처리단에서 `latin-1` 코덱 에러 유발.
*   **토큰 파싱 정규식 만료**: 애플 앱스토어 웹 페이지 HTML 레이아웃이 최근 개편되어 라이브러리 내부에 하드코딩된 JWT 토큰 추출용 메타 태그 정규식(`<meta.+web-experience-app/config/environment`)이 더 이상 작동하지 않아 bearer token을 획득하지 못하고 최종 API 호출이 차단됨.

### 3. 해결책 (Resolution)
*   **공식 iTunes RSS Feed API로 전환**: 웹 페이지 파싱 및 외부 Scraper 라이브러리 의존성을 제거하고, 인증과 토큰이 필요 없는 공식 iTunes RSS Feed JSON API를 직접 호출하도록 함수를 재설계.
*   **안정적인 예외 처리**: `page=1`부터 `10`까지 최대 500개의 리뷰를 수집하며 `requests` 타임아웃(10초) 및 JSON 파싱 에러 방어 코드를 구현하여 안정적 수집 파이프라인 확보.

## 📌 Case 2. 단어 네트워크 연결 중심성 쏠림 및 완전 그래프화 현상
### 1. 현상 (Symptom)
*   NetworkX를 활용한 단어 공동 출현(Co-occurrence) 분석 시, 상위 30개 고빈도 형태소 노드의 연결 중심성(Degree Centrality)이 대부분 **`1.000`**으로 조출됨.
*   시각화 결과 모든 노드가 엣지로 촘촘히 엮여 스파게티처럼 뭉치는 현상이 발생하여, 비즈니스 가치가 있는 허브 키워드를 식별하기 불가능해짐.

### 2. 원인 분석 (Root Cause)
*   **데이터 규모 대비 임계치 불균형**: 수집된 9,654건의 대용량 데이터 코퍼스 크기에 비해, 동시 출현 인정 임계치(`THRESHOLD = 15`)가 너무 낮게 설정되어 상위 고빈도어들이 웬만한 문서들 사이에서 쉽게 중복 출현 조건(15회 이상)을 달성하여 모든 노드 간의 선이 연결되는 완전 그래프(Complete Graph)가 형성됨.

### 3. 해결책 (Resolution)
*   **임계값(THRESHOLD) 상향 조정**: 동시 출현 임계치를 데이터셋 크기에 비례하여 **`THRESHOLD = 150`**으로 대폭 상향 조정.
*   **결과**: `'이용'(0.517)`과 `'대여'(0.310)`만 중심에 지배적 허브 노드로 살아남고, `'시간'`, `'반납'`, `'연결'` 등이 코어 엣지를 형성하는 형태의 유의미한 컴포넌트가 드러남. `'로그인'`, `'고장'`, `'지도'` 등은 고립 노드로 자연 격리되어 모듈형 독립 이슈임을 정량적으로 시각화하는 데 성공.

## 📌 Case 3. 비지도 토픽 모델링(LDA)의 비즈니스 라벨링 정합성 이탈
### 1. 현상 (Symptom)
*   학습된 4개 토픽에 할당된 실측 키워드(예: 편리, 감사, 운동, 이동)가 미리 지정해 둔 딕셔너리 라벨(`'토픽 1: 서버 에러(500) 및 로그인 불가'`)과 매칭되지 않고 꼬여서 리포트되는 모순이 발견됨.

### 2. 원인 분석 (Root Cause)
*   **비지도 학습의 무작위성**: LDA 알고리즘은 비지도 학습이므로 매 실행 시마다 토픽 인덱스(0, 1, 2, 3)가 무작위로 배정되고 군집이 결정됨.
*   **일반 노이즈 단어의 간섭**: `'이용'`, `'시간'`, `'만들'`, `'경우'` 등의 범용 명사/어근이 불용어로 걸러지지 않아 토픽별 경계를 흐리게 만들고 고유 키워드(예: 개발자모드)의 상위 랭킹을 흐려놓음.

### 3. 해결책 (Resolution)
*   **지배적 토픽 문서 점유율 검증 코드 도입**: 각 문서의 `Dominant Topic`을 구하고 코퍼스 내 점유 비율을 계산하는 정량 분포표(Table) 생성 로직을 도입하여 토픽 0(**27.26%**), 토픽 1(**28.04%**), 토픽 2(**8.09%**), 토픽 3(**36.61%**)의 정량적 분포 증명.
*   **실측 기반 동적 라벨링 적용**: 정량 비중과 실측 키워드 트렌드에 의거하여 토픽 1은 기존 오류가 아닌 '출퇴근/운동의 긍정 경험'으로, 토픽 3은 '로그인/결제 시스템 장애'로 팩트 정밀 매핑을 사후 보정 완료.
