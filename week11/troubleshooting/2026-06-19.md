# 📅 RAG 및 Ragas 평가 시스템 트러블슈팅 리포트 (2026-06-19)

오늘 실습 중 Advanced RAG 구축 및 Ragas 평가 시스템 연동 과정에서 발생한 핵심 문제들과 해결 과정을 정리한 트러블슈팅 문서입니다. 추후 포트폴리오 자산으로 활용할 수 있도록 현업 관점에서 기록되었습니다.

## 🚨 1. Chroma DB 임베딩 차원 수 불일치 에러 (InvalidArgumentError)

### 1.1 현상
Chroma DB에 청크를 저장하거나 쿼리를 조회할 때 다음과 같은 예외가 발생하며 프로세스가 중단됨.
```
InvalidArgumentError: Collection expecting embedding with dimension of 256, got 1024
```

### 1.2 원인
* 노트북 상단에서 **Gemini Embeddings** 모델을 사용하여 256차원 스키마로 Chroma DB 컬렉션을 최초 빌드함.
* 중간에 임베딩 성능 향상을 위해 **BAAI/bge-m3** (기본 1024차원) 모델로 임베딩 객체를 재할당한 후 DB에 접근하려 시도함.
* Chroma DB 내부 컬렉션은 차원(dimension)이 고정되는 스키마 제약이 있어, 1024차원 데이터의 입력을 거부함.

### 1.3 해결 (Trouble-Cured)
* 실습에 사용 중인 임베딩 모델을 하나로 통일함.
* 인메모리(In-Memory) 크로마 DB 환경의 이점을 활용하여, 주피터 노트북의 상위 셀(임베딩 모델 선언 및 Chroma DB 초기화 셀)부터 순차적으로 다시 실행하여 데이터베이스의 임베딩 차원 스키마를 BAAI/bge-m3 기준(1024차원)으로 정렬 및 동기화함.

## 🚨 2. Ragas API 과도기 버전 불일치 문제 (TypeError & ValueError)

### 2.1 현상
Ragas 평가 실행을 위해 메트릭을 초기화하거나 `evaluate()` 함수를 실행할 때 연속적으로 다중 에러 발생.
1. `TypeError: All metrics must be initialised metric objects, e.g: metrics=[BleuScore(), AspectCritic()]`
2. `TypeError: Faithfulness.__init__() missing 1 required positional argument: 'llm'`
3. `ValueError: Collections metrics only support modern InstructorLLM. Found: LangchainLLMWrapper.`

### 2.2 원인
* **Ragas 라이브러리의 버전 과도기(v0.2.x) 아키텍처 불일치**가 근본 원인.
* 신형 메트릭(`Faithfulness()`)은 `SimpleBaseMetric`을 상속하고 구조화된 검증을 위해 `instructor` 기반의 전용 Ragas LLM 주입을 요구함.
* 반면, 평가 엔진인 `evaluate()` 함수는 여전히 내부 타입 검사에서 구형 `Metric` 클래스만 받도록 하드코딩되어 있어 신형 메트릭 전달 시 `TypeError`를 던짐.
* 신형 메트릭 클래스는 기존 LangChain 래퍼인 `LangchainLLMWrapper`를 최신 규격이 아니라는 이유로 거부함.

### 2.3 해결 (Trouble-Cured)
노트북 환경에서 복잡한 `@experiment` 프레임워크로 완전 이전하지 않고, 기존 RAG 평가 데이터셋 포맷을 유지하면서 에러를 우회하는 최선의 대안을 적용함.
1. Python **`warnings` 필터링**을 적용하여 과도기적 `DeprecationWarning` 메시지들을 소거 처리함.
2. `evaluate()`의 엄격한 타입 가드를 통과하기 위해 구형 소문자 메트릭 인스턴스(`faithfulness`, `answer_relevancy` 등)를 소괄호 `()` 없이 리스트로 구성함.
3. 구형 메트릭 인스턴스들과 호환되는 `LangchainLLMWrapper` 및 `LangchainEmbeddingsWrapper`를 결합하여 최종 평가를 무사히 실행함.

## 🚨 3. 평가 결과 DataFrame 시각화 에러 (KeyError)

### 3.1 현상
평가 완료 후 `result.to_pandas()` 데이터프레임에서 특정 열을 필터링하여 출력하려 할 때 `KeyError` 발생.

### 3.2 원인
Ragas 평가 데이터셋 결과의 실제 컬럼명과 코드에서 요청한 타겟 컬럼명 간의 매핑 차이.
* 요청 컬럼: `["question", "answer", "answer_relevance"]`
* 실제 컬럼: `["user_input", "response", "answer_relevancy"]`

### 3.3 해결 (Trouble-Cured)
Pandas DataFrame의 실제 스키마 컬럼명을 확인하고 매핑을 일치시켜 해결함.
```python
display(df_result[["user_input", "response", "faithfulness", "answer_relevancy", "context_precision", "context_recall"]])
```

## 📊 4. 분석적 이슈: 표 데이터 파싱 한계로 인한 Faithfulness 0.0 저평가

### 4.1 현상
답변 자체는 팩트(980명)에 완벽하게 일치했으나, `faithfulness` 메트릭이 `0.0`으로 측정됨.

### 4.2 원인
* 원본 회의록 텍스트 내부 정보가 마크다운 표(Table) 포맷으로 기재되어 있음.
* Ragas NLI(자연어 추론) 평가기가 마크다운 격자 지시자(`|`) 구조를 읽고 올바른 사실 명제로 매핑해 내지 못해 오작동(False Negative)을 일으킴.

### 4.3 향후 개선 방향
* **자연어 서술화(Textualization)**: 전처리 과정에서 표의 각 행을 읽어 템플릿 기반 줄글로 가공하여 주입.
* **HTML 구조 변환**: 마크다운 대신 LLM이 인지하기 쉬운 `<table>` 규격으로 포맷팅을 치환하여 인덱싱 진행.
