## 1. LangChain Hub의 Public Prompt Pull 관련 ValueError 발생
- **현상**: ReAct 에이전트 구동을 위해 `hub.pull("hwchase17/react")`를 호출했을 때, 아래와 같은 예외가 발생하며 중단되었습니다.
  ```text
  ValueError: Pulling a public prompt by owner/name is disabled by default because prompts may contain untrusted serialized LangChain objects. If you trust this prompt, set `dangerously_pull_public_prompt=True` to acknowledge the risk.
  ```
- **원인**: Langsmith 및 LangChain Core 보안 패치(GHSA-c67j-w6g6-q2cm 관련)에 따라, 외부 원격 리포지토리(LangChain Hub)로부터 public prompt를 가져올 때 발생할 수 있는 임의 코드 실행(Arbitrary Code Execution) 위험을 방지하기 위해 기본적으로 Public prompt pull이 비활성화되었습니다.
- **해결**: 
  1. (프로덕션 추천 방식) 네트워크 호출 및 외부 의존성을 제거하고 런타임 안정성을 보장하기 위해, ReAct 템플릿의 문자열을 로컬에 `PromptTemplate` 객체로 직접 정의하여 우회했습니다.
  2. (Hub 동기화 대안 방식) 기존의 `hub.pull`을 유지하면서 가져오려면 `dangerously_pull_public_prompt=True` 매개변수를 활성화하여 명시적으로 위험을 승인하도록 코드를 업데이트했습니다.
- **교훈**: 프로덕션 배포 레벨의 시스템을 설계할 때는 원격 API 서버나 외부 저장소(Hub)에 대한 런타임 의존성을 가급적 최소화(로컬화)하여 시스템의 가용성과 보안성을 유지하는 것이 현업의 핵심 원칙입니다.

## 2. ReAct 에이전트 도구 호출 시 Pydantic ValidationError 발생
- **현상**: `AgentExecutor` 실행 시 곱셈 도구(`calculate_multiply`)가 호출되면서 아래와 같은 Pydantic `ValidationError` 에러가 발생했습니다.
  ```text
  ValidationError: 2 validation errors for calculate_multiply
  a
    Input should be a valid number, unable to parse string as a number [type=float_parsing, input_value='354.2, 12.8', input_type=str]
  b
    Field required [type=missing, input_value={'a': '354.2, 12.8'}, input_type=dict]
  ```
- **원인**: ReAct 에이전트 프롬프트 아키텍처는 LLM으로 하여금 도구 호출을 위한 입력값을 단일 문자열(`Action Input: 354.2, 12.8`) 형태로 뱉어내게 합니다. 하지만 도구 함수가 복수의 float 매개변수(`a: float, b: float`)로 명세되어 있으면, LangChain 내부에서 입력 문자열 전체를 첫 번째 매개변수 `a`에 밀어 넣으려다 타입 변환 오류가 나고 `b` 값은 누락되었다고 판단하게 됩니다.
- **해결**: 도구의 시그니처를 단일 문자열(`query: str`)로 변경하고, 내부에서 `split(",")`을 통해 수동으로 슬라이싱 및 형변환 처리를 하도록 함수 로직을 수정했습니다.
- **교훈**: ReAct 에이전트와 도구를 결합할 때는 다중 파라미터(Multi-argument) 방식보다 **단일 문자열 입력(Single-string Input)**으로 정의하고 내부 파싱 처리를 하는 것이 타입 불일치 에러를 방지하는 실무적 모범 사례입니다. (다중 파라미터를 그대로 사용하고 싶다면 도구 호출 형식을 JSON으로 완벽히 강제할 수 있는 Structured Tool 이나 Tool Calling Agent 등의 아키텍처로 격상해야 합니다.)
