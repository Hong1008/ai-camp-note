# [Senior Mentor] 2026-06-17 트러블슈팅 리포트

## 1. Vector DB (Chroma) 중복 데이터 적재로 인한 검색 결과 왜곡
- **현상**: RAG 검색 시 동일한 내용의 문서(`SK-PET-2026`)가 중복하여 3개 이상 출력되었으며, 이로 인해 한정된 LLM 컨텍스트 공간이 낭비되고 다른 유관 문서(보안 구역 출입 요건 등)가 검색 영역에서 밀려나 답변이 누락되는 현상이 발생했습니다.
- **원인**: Chroma의 `from_documents()` 및 `add_documents()` API는 호출될 때마다 기존 컬렉션의 데이터를 삭제하지 않고 덧붙이는(Append) 방식으로 작동합니다. 주피터 노트북 환경에서 셀을 여러 번 재실행하면서 동일한 임베딩 벡터가 중복 누적되었습니다.
- **해결**: 데이터 적재 셀 상단에 기존 컬렉션을 명시적으로 삭제하는 `delete_collection()` 코드나 로컬 저장 디렉터리를 비우는 초기화 로직을 추가하여 실행 시마다 항상 깨끗한 상태(Clean Build)에서 DB가 구축되도록 개선했습니다.
- **교훈**: RAG 시스템의 안정성을 위해서는 데이터베이스의 생명 주기(Life Cycle)와 적재 방식을 정교하게 통제해야 데이터 오염을 예방할 수 있습니다.

## 2. ParentDocumentRetriever 생성 시 SemanticChunker 타입 검증 에러
- **현상**: `ParentDocumentRetriever` 인스턴스화 과정에서 부모 스플리터(`parent_splitter`) 매개변수에 `SemanticChunker` 객체를 주입하자 Pydantic `ValidationError`가 발생했습니다.
  ```text
  ValidationError: 1 validation error for ParentDocumentRetriever
  parent_splitter
    Input should be an instance of TextSplitter [type=is_instance_of, input_value=<SemanticChunker...>, input_type=SemanticChunker]
  ```
- **원인**: `ParentDocumentRetriever`는 Pydantic 검증을 위해 `parent_splitter`가 `TextSplitter`를 상속받을 것을 요구하지만, LangChain의 `SemanticChunker`는 의미적 문장 유사성 기반의 복잡한 변환을 수행하기 위해 `BaseDocumentTransformer`를 상속받고 있어 타입 불일치가 발생했습니다.
- **해결**: 리트리버 선언 시 `parent_splitter=None`으로 비워두어 내부의 자동 분할 로직을 비활성화하고, 개발자가 직접 `SemanticChunker`로 분할한 문서 결과물(`semantic_chunks`)을 `retriever.add_documents(semantic_chunks)` 형태로 직접 주입하는 수동 매핑 방식으로 우회하여 성공했습니다.
- **교훈**: 프레임워크의 엄격한 타입 제약이 있을 때, 내부 매핑 원리(None 주입 시 문서 자체를 부모로 인정함)를 파악하면 코드 수준의 우회 방안을 주도적으로 설계할 수 있습니다.
