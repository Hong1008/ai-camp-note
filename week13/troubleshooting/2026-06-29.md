# 🔍 Troubleshooting: LM Studio API 스트리밍 및 LangChain 연동 이슈 (2026-06-29)

## 1. 문제 현상 (Issue Description)
로컬 환경의 LM Studio 서버에 `google/gemma-4-e2b` (추론형 모델)을 로드한 뒤, Python 클라이언트 및 LangChain을 연동하는 과정에서 아래 두 가지 장애 현상이 관측되었습니다.

1. **API 스트리밍 및 일반 호출 시 최종 답변 누락**:
   * API 호출 결과, 모델의 생각 과정(Thinking Process)만 출력되거나 그마저도 중간에 끊긴 채 최종 텍스트 답변이 아예 반환되지 않음.
2. **LangChain (`ChatOpenAI`) 연동 시 Hanging 현상**:
   * `llm.invoke()`를 실행했을 때 프로그램이 응답을 받지 못하고 계속 블로킹(대기) 상태를 유지하여 빈 출력만 생성됨.

---

## 2. 원인 분석 (Root Cause Analysis)

### 2.1. 토큰 제한 조기 고갈 (Truncation by Token Limit)
LM Studio에서 수신한 원본 응답 통계(`stats`)를 보면 다음과 같은 지표가 확인됩니다.
```json
"stats": {
  "input_tokens": 19,
  "total_output_tokens": 100, // 👈 요청한 max_output_tokens 한계치
  "reasoning_output_tokens": 97 // 👈 생각 과정(Reasoning)에 소모한 토큰
}
```
* Gemma 4와 같은 추론 모델은 답변 전에 생각 과정(Thinking Process)을 먼저 생성합니다. 
* 설정된 `max_output_tokens`가 `100`으로 너무 작아서, **생각을 진행하는 동안 이미 97토큰을 다 써버렸고**, 실제 최종 답변(Content)을 뱉기 직전(남은 3토큰 내)에 API 출력이 강제 중단되었습니다.

### 2.2. 비표준 필드 매핑 및 LangChain 파싱 오류
OpenAI 규격을 따르는 로컬 API 호출 시, LM Studio는 다음과 같은 형태로 JSON 데이터를 넘겨줍니다.
```json
"message": {
  "role": "assistant",
  "content": "", // 👈 실제 답변 (비어 있음)
  "reasoning_content": "\nThinking Process:\n..." // 👈 생각 과정
}
```
* **LangChain의 `ChatOpenAI`**는 표준 규격에 따라 `message.content` 필드만 파싱하여 사용자에게 반환합니다.
* 하지만 모델이 아직 생각을 다 끝내지 못했거나 토큰 고갈로 답변을 시작도 못한 상태이므로 `content` 필드는 물리적으로 비어 있습니다(`""`). 이로 인해 LangChain은 아무런 출력을 내지 못하게 됩니다.
* 또한, 로컬 추론 모델 특성상 생각이 길어질 경우 생성 속도 제약으로 인해 동기 호출이 끝날 때까지 10~30초 이상 블로킹되어 마치 프로그램이 먹통(Hanging)이 된 것처럼 체감됩니다.

---

## 3. 해결 방안 및 조치 (Resolution)

### 3.1. 토큰 크기 확장 (`max_output_tokens` ➔ 1000)
요청 Payload의 `max_output_tokens`를 `1000` 이상으로 설정하여 모델이 생각을 마친 후 실제 답변을 완성할 수 있을 만큼의 충분한 토큰 여유를 주었습니다.

### 3.2. SSE(Server-Sent Events) 이벤트 분기 파싱 코드 구현
스트리밍 방식으로 호출할 때, `event: reasoning.delta`와 `event: message.delta`를 각각 별도 라인으로 파싱하여 실시간으로 출력하도록 로직을 재설계했습니다.
```python
if current_event == "reasoning.delta":
    print(content, end="", flush=True) # 생각 과정 실시간 렌더링
elif current_event == "message.delta":
    print(content, end="", flush=True) # 최종 답변 실시간 렌더링
```

### 3.3. LangChain `additional_kwargs` 매핑 활용
LangChain 연동 시에는 `response.additional_kwargs.get("reasoning_content")`를 통해 모델의 숨겨진 생각을 직접 끄집어내어 활용할 수 있도록 연동 규격을 수정하였습니다.
