# [에이전트] 2026-06-25 트러블슈팅 리포트

## 1. VS Code 에디터 내 Python 타입 체킹(Type Checking) 미동작
- **현상**: 주피터 노트북 내에서 타입 어노테이션 불일치(예: `def add_price(a:int, b:int)` 함수에 `"1000"`을 전달하는 등)가 발생해도 에디터 상에서 아무런 경고나 에러 표시가 나타나지 않음.
- **원인**: VS Code의 기본 파이썬 정적 분석 엔진인 Pylance의 타입 체킹 모드(`python.analysis.typeCheckingMode`)가 전역/작업 영역 설정에서 `off`로 지정되어 정적 검사가 작동하지 않았음.
- **해결**: 프로젝트 루트의 `.vscode/settings.json` 파일에 `"python.analysis.typeCheckingMode": "basic"` 설정을 추가하여 정적 검사 활성화.
- **교훈**: 파이썬은 런타임에 타입을 검증하지 않는 동적 타이핑 언어이므로, 개발 단계의 정적 안정성을 보장받으려면 IDE 분석 도구의 옵션을 반드시 명시적으로 제어해야 함.

## 2. LangGraph 퀴즈 채점 노드 내 AttributeError (리스트 객체 strip 시도)
- **현상**: `app.invoke()`를 실행하는 과정에서 `grader` 노드 실행 중 `AttributeError: 'list' object has no attribute 'strip'` 오류가 발생하여 전체 상태 머신이 비정상 종료됨.
- **원인**: LLM 모델(Gemma-4, Gemini 등)의 API 응답이나 특정 메시지 포맷에 따라 `message.content`가 단순 문자열(`str`)이 아니라, 멀티모달용 정보가 포함된 구조화된 리스트 `[{'type': 'text', 'text': '...'}]` 형태로 들어와 `.strip()` 문자열 메서드 호출 시 에러가 유발됨.
- **해결**: 노드 내에서 `last_content`의 인스턴스 타입을 사전 검사하여, 리스트 형식일 경우 내부 딕셔너리에서 `"text"` 값을 추출해 문자열로 병합하고 그 외의 경우에는 일반 `str()` 형변환을 가하도록 방어 로직을 적용.
- **교훈**: LLM 응답 데이터 구조는 비결정적이거나 모델 스펙에 따라 런타임에 동적으로 변경될 수 있으므로, 상태 업데이트를 처리하는 노드 내부에서 타입 가드(Type Guard) 및 데이터 유효성 검증을 엄격히 적용해야 견고한 에이전트를 구축할 수 있음.
