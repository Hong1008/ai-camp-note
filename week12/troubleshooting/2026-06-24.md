# 트러블슈팅 리포트 (2026-06-24)

## 1. 문제 상황 (Problem Description)
- **현상**:
  - CrewAI 분석을 실행한 후 Streamlit 대시보드 렌더링 영역에서 아래와 같은 오류가 발생하며 대시보드가 정상적으로 응답하지 않음.
    1. `JSONDecodeError: Expecting value: line 1 column 1 (char 0)`
    2. `AttributeError: 'list' object has no attribute 'get'`
  - 에이전트가 정상적인 JSON 문자열이 아닌 마크다운 텍스트를 반환하거나 스키마 규격을 무시하고 리스트(`list`) 형식의 데이터를 반환했을 때, 프론트엔드(`app.py`) 단에서 타입 검증 없이 `dict`라고 신뢰하고 `.get()` 메소드를 호출하다가 전체 렌더링 엔진이 정지함.

---

## 2. 원인 분석 (Root Cause)
- **에이전트 단의 예외 은폐 (Silent Failure)**:
  - `agent.py` 내부에서 크루 분석 결과를 직렬화할 때, `try-except` 구문이 결과 파싱 과정의 예외를 잡아 단순히 `{"error": "결과 파싱 오류: ..."}` 형태의 문자열로 변환하여 정상 리턴했음.
  - 이로 인해 `app.py`는 분석 로직 자체는 성공(Success)으로 인지하고 해당 반환값을 캐시에 저장했으나, 실제 렌더링 루프 진입 시 기대한 키(`title`, `summary_table` 등)가 존재하지 않아 빈 카드만 노출되는 등의 불완전 상태(Silent Failure)가 야기됨.
- **타입 검증 결여**:
  - LLM 모델의 성능 제약이나 컨텍스트 제어로 인해 structured output 스펙을 만족하지 못한 `list`나 원본 마크다운 텍스트가 전달될 경우, `json.loads()`는 정상 동작하더라도 반환된 객체가 `dict`가 아닌 `list` 형태로 구성될 수 있음. 이 경우 `.get()` 접근을 시도하면 즉시 `AttributeError`가 발생해 화면을 중단시킴.

---

## 3. 해결 방안 (Resolution)

### 백엔드 (Agent) 단의 예외 처리 로직 수정
- 에이전트 분석 모듈([agent.py](file:///home/hong/project/ai-camp-note/week12/mini-project/agent.py))에서 에러를 인위적으로 포맷팅하여 리턴하는 기존 코드를 제거하고, 명시적인 타입 체크를 수행하여 이상 데이터 감지 시 예외를 상위 호출부로 명확히 던지도록 변경했습니다.
```python
# agent.py 수정 부분
# Pydantic 결과 리턴 (구조화된 출력이 확보되지 않은 경우 예외 발생)
if hasattr(result, "pydantic") and result.pydantic:
    if hasattr(result.pydantic, "model_dump_json"):
        return result.pydantic.model_dump_json()
    return result.pydantic.json()
elif hasattr(result, "json_dict") and result.json_dict:
    return json.dumps(result.json_dict, ensure_ascii=False)

# 결과 문자열이 JSON 형식인지 검증 및 타입 분기
try:
    raw_str = str(result)
    parsed = json.loads(raw_str)
    if isinstance(parsed, dict):
        return raw_str
    elif isinstance(parsed, list):
        raise TypeError(f"CrewAI 결과가 dict가 아닌 list 형식입니다: {parsed}")
except json.JSONDecodeError:
    pass
    
raise ValueError(f"CrewAI가 구조화된 데이터(StrategyReport)를 생성하지 못했습니다. 결과: {result}")
```

### 프론트엔드 (Streamlit) 단의 입력 데이터 유효성 검사 추가
- `app.py` 단에서 세션 데이터를 JSON으로 파싱한 직후, 파싱된 객체가 정상적인 `dict` 구조인지 강하게 검증하는 안전장치를 추가했습니다.
```python
# app.py 수정 부분
report_data = json.loads(raw_content)
if not isinstance(report_data, dict):
    raise TypeError(f"AI 분석 결과가 올바른 딕셔너리 구조가 아닙니다. 실제 타입: {type(report_data)}, 데이터: {report_data}")
```
- 이를 통해 분석 프로세스 실패 또는 스키마 위반 데이터 유입 시, 오류가 은폐되지 않고 즉시 명시적인 트레이스백(Traceback)을 노출하며 빠른 인지 및 디버깅이 가능하도록 시스템 안정성을 극대화했습니다.

## 4. 교훈 및 피드백 (Lessons Learned)
1. **에러는 가능한 가장 빨리, 가장 시끄럽게 울려야 한다 (Fail-Fast)**:
   - 프로덕션 환경의 복잡한 멀티 에이전트 시스템일수록 에러를 중간에 모호하게 가공하여 반환하는 패턴은 디버깅을 어렵게 만듭니다. 예외 상황이 발생하면 즉시 예외를 발생(raise)시켜 전파하는 것이 디버깅 코스트를 비약적으로 단축시킵니다.
2. **LLM 구조화 데이터의 프론트엔드 검증 필수**:
   - LLM 출력이 Pydantic으로 보장되더라도 런타임 환경에서는 예상치 못한 포맷 위반이 늘 발생할 수 있으므로, 최종 소비처(UI 컴포넌트) 직전에서 타입 체크(Type-guard)를 한 번 더 구현하는 디자인 패턴이 권장됩니다.
